# Contributing to Open AMPP

Thanks for wanting to help! Open AMPP is young, so every bug report, test on real hardware, translation or pull request makes a real difference. Issues and pull requests are welcome in **English or Spanish** (¡también en español!).

## Ways to help

- **Try it and tell us what broke.** The x64 builds for macOS and Linux have never run on real machines; a report from one is gold. Use the [bug report form](https://github.com/Jmzp/open-ampp/issues/new?template=bug_report.yml).
- **Share your migration story.** Coming from XAMPP, MAMP, Laragon or Docker? Tell us what was missing or confusing in an issue: it makes the next person's switch smoother.
- **Pick an issue.** Look for [`good first issue`](https://github.com/Jmzp/open-ampp/labels/good%20first%20issue) and [`help wanted`](https://github.com/Jmzp/open-ampp/labels/help%20wanted). Comment on it before you start so nobody duplicates work.
- **Build a roadmap item.** The [roadmap](README.md#%EF%B8%8F-roadmap) lists what is next (`*.localhost` domains, per-project PHP versions, HTTPS with a local CA). Open an issue to agree on the design first.
- **Improve the docs or the translations.**

Found a security problem? Do **not** open a public issue: see [SECURITY.md](SECURITY.md).

## Setting up

You need **Rust** (stable, via [rustup](https://rustup.rs)) and **Node.js 22**, plus the system pieces Tauri needs:

| System | Also install |
|---|---|
| Windows | Visual Studio Build Tools with **Desktop development with C++**, and WebView2 (preinstalled on Windows 11) |
| macOS | Xcode Command Line Tools (`xcode-select --install`) |
| Linux (Debian/Ubuntu) | `sudo apt install libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf` |

See [Tauri's prerequisites](https://v2.tauri.app/start/prerequisites/) for other distros.

```sh
git clone https://github.com/Jmzp/open-ampp.git
cd open-ampp/apps/desktop
npm ci
npm run tauri dev        # runs the app with hot reload for the UI
```

> **Windows PowerShell:** if `npm` fails with "running scripts is disabled", call `npm.cmd` instead (e.g. `npm.cmd run tauri dev`).

The app uses your normal data folder. To keep your real setup untouched while developing, point it somewhere else:

```sh
OPEN_AMPP_HOME=/tmp/ampp-dev npm run tauri dev            # macOS / Linux
$env:OPEN_AMPP_HOME="$env:TEMP\ampp-dev"; npm.cmd run tauri dev   # Windows PowerShell
```

`OPEN_AMPP_LANG=en` (or `es`) forces the language of the Rust-side messages; the UI follows the system language.

## Where things live

| You want to change… | Look at |
|---|---|
| How services start, stop or are detected | `crates/ampp-core/src/services.rs` |
| Generated `httpd.conf`, `php.ini`, `my.cnf` | `templates/` and `crates/ampp-core/src/config.rs` |
| Downloads, checksums, extraction | `crates/ampp-core/src/installer.rs` |
| Versions offered for download | `catalog/manifest.json` (generated by `catalog/generate.py`) |
| The `ampp` command | `crates/ampp-cli/src/main.rs` |
| Tauri commands, tray | `apps/desktop/src-tauri/src/` |
| Screens | `apps/desktop/src/pages/` and `apps/desktop/src/components/` |
| UI texts | `apps/desktop/src/lib/i18n.ts` |

The README's [How it works](README.md#%EF%B8%8F-how-it-works) section explains the architecture.

## Tests

```sh
cargo test -p ampp-core -p ampp-cli      # what CI runs: fast, offline
cd apps/desktop && npm run build         # type-checks and builds the UI
```

- `crates/ampp-core/tests/supervisor.rs` exercises the real process supervisor with fake services (the test binary pretends to be Apache, PHP and MariaDB), so service changes can be tested without downloading anything.
- `crates/ampp-cli/tests/cli.rs` runs the `ampp` binary against a temporary `OPEN_AMPP_HOME`.
- `cargo test -p ampp-core -- --ignored` adds tests that download real binaries (needs network).
- Coverage: `cargo install cargo-llvm-cov`, then `cargo llvm-cov -p ampp-core -p ampp-cli`.

New behaviour should come with a test. If something can only be checked by hand (an installer, a platform you tested on), say so in the pull request.

## Conventions

- **English** for code, comments, commit messages and pull request titles. Conversation in issues can be in English or Spanish.
- **Every user-facing text in both languages**: `tr!("español", "English")` in Rust, both entries in `i18n.ts` in the UI.
- **Match the surrounding code**: Rust lines go up to about 120 characters and the code is not run through `cargo fmt`, so do not reformat files you are not changing. Keep comments short and explain *why*.
- **Safe by default**: services listen on `127.0.0.1` only; downloads are always verified with SHA-256.
- **Commits**: short imperative subject, optionally prefixed with the area (`Apache: …`, `Catalog: …`, `README: …`), and a body explaining why when it is not obvious.

## Pull requests

1. Fork the repository and create a branch from `main`.
2. Make your change with its tests, and run the commands above.
3. Open the pull request and fill in the template. Link the issue it closes (`Closes #123`).
4. CI runs on Windows, macOS and Linux; a maintainer will review it. Small, focused pull requests get reviewed fastest.
